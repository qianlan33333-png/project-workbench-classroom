# 原答疑语料的标准组件适配

业务方法沿用旧专家版本 `9e52d33fcb1531dbd6f91baf0eb14445643a9d25920f6e355de77778b10c8874` 的 qa_sync.py；qa_gate.py、qa_retrieve.py 和知识文件继续来自原部署，不复制真实资料进 Git。

变动仅为：同步状态改为 MySQL DB-API，固定操作编号的不可变发布目录，索引失败阻止发布，增量窗口按原检查点回退72小时。原来的 `min(checkpoint-72h,now-30d)` 会每日重复读取整月，修正为实际72小时增量；新客户仍读30天。相邻问答仍是候选，绝不自动升级为可答政策。

`qa_refresh` 是普通 MCP 资料来源工具，由本人配置的连接、Temporal资源刷新和08:30 Schedule调用，不开放给客户Agent。返回通用 records/watermark，Host无需了解业务。收集中不更新生产读取指针；仅全部视图、材料和索引成功后交给工作台原子发布。

MCP Resources提供知识文档的目录和正文；客户工具仍只开放 qa_search/qa_read/qa_check。凭据只在私有 service 配置中，按宿主绑定项目/会话解析实际固定资料版本。旧版根目录保留为基线资源，所有新快照在独立版本目录，避免递归索引。

增量不是只登记一份清单：MySQL同步完成后导出本轮固定的records/links JSONL，原qa_retrieve只将这层输入接回既有混合检索及证据检查。JSONL参与指纹，新记录能按原始消息ID读取；模型不直接查询活动中的采集表。旧基线无快照配置时继续使用原读取方式。原qa_retrieve SHA256为 `cc2df37fd6b5cfa5efec83dd945c1830e997f41a14d8aefc9ac740ee684c053a`，算法、模型、分块、排序及门控均未重写。

快照克隆复用不可变归档/索引分片的硬链接，JSON、JSONL及SQLite缓存独立复制；原写入方法通过临时文件原子替换，不能原位修改共享文件。业务源数据不是程序回滚版本，发布清理不得删除它。
