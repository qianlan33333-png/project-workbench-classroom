# 工作台扩展

先判断变化属于哪一层：

- 新数据来源、板块或共享范围：注册连接、资源和项目引用。不要为资源编号写工具分支。
- 新判断方法或内容风格：建立 Agent Skills 方法包及可版本化的方法资源。方法里选择需要的资料板块、输入预算、输出 Schema 和失败处理。
- 新外部系统能力：优先成熟 MCP 服务或官方连接器；确有缺口才写薄适配。
- 新执行组合：复用 `program_run` 的拉取/发布/生成组合，或用 Temporal 官方 SDK 增加通用工作流。不要发明 YAML/JSON 编排语言。

实现接口和调用规则见 [扩展契约](../../docs/EXTENSIONS.md)。读相关章节即可，不加载用户全量数据。

专家只决定目标、资料选择和方法。稳定取数、切片、页游标、并发、重试、逐条结果与发布由程序完成。工具返回引用和必要摘要，禁止把几千人原文放进主对话。

Agent 不接收数据库凭证，不可用输入 `project_id` 选择身份。新增工具遵守宿主已绑定的项目/Session；共享读取仍通过资源工具，衍生产物携带来源引用。额外 MCP 插件是本人安装的可信程序，不能绕过资源工具直接抓取其他项目数据。

修改外部系统时使用稳定幂等键。接收、待手机确认、发送、送达分别报告；结果未知先查询原回执，不能重发。涉及客户发送沿用本人确认，专家不能调用确认接口。

新增能力至少用两个不同领域验证接口无需改动。覆盖重复提交、取消/重启、撤销共享和外部结果未知中实际相关的路径。只在明确授权范围内联测真实渠道，模拟结果不能充当送达证据。

不要把凭证、真实样本、聊天日志或客户产物放进包、Git 或 Skill。专家方法不自动吸收项目笔记。
