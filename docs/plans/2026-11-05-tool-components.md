# 通用工具组件落地顺序

依据已确认的一期PRD v1.1，先交付可独立核查的通用接入项，再接数据业务插件。

1. 复用MCP登记，受管组件绑定项目和动作，禁止原生Harness直连绕过。
2. 受管调用补稳定请求键，宿主仅保存调用引用；插件拥有真实业务任务。
3. 原Session展示异步状态与结果，状态轮询独立且有界，不阻塞现有定时和协作。
4. 验证并发提交、迟到响应/取消、跨项目、停用、回收/删除、启动恢复、协议反向请求与饥饿。
5. 独立/re→修复→复审，真实Harness和桌面/手机页面验收后，才按固定入口发布。
6. 下一项：独立数据插件、只读源合同、新MySQL、固定清洗和发布水位；原中心继续运行。

参考案例已在v1.1中完成核对：MCP结构化工具结果与VS Code宿主通用入口/扩展具体能力的分工。当前实现不引入通用业务执行平台。
