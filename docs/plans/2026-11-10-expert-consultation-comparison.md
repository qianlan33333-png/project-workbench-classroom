# 专家分析能力：真实模型与语料对照

本轮使用正式答疑语料固定版本 `ebee3f88-614e-5350-84c0-d87f57e31108`、真实DeepSeek Flash和原证据工具。用户问题是脱敏构造的验收对话；发送进入隔离收件器，没有向真实客户发送。本报告不是新的企微实收证明。

旧版为已安装的2.0.0专家、原off设置；新版为2.1.0专家及同一模型的high原生思考。二者使用独立固定Session、同一组输入及同一资料版本。因此本对照评估的是两项改动的组合，不把全部改善归功于提示词。

## 可以直接比较的结果

| 输入或情境 | 原版表现 | 新版表现 |
|---|---|---|
| 开始深度咨询 | 本次重跑也能询问背景；没有故意挑成最差答案 | 询问当前目标、现状和卡点 |
| 小公司运营、每周三个晚上、不辞职 | 本次原版在引用取证未通过后转人工，无客户回复，连续流程止于此 | 根据时间约束先缩小问题，再问能否接触真实需求 |
| 演示得到“还行” | 原版已转人工，后续没有回复，不编造对照 | 区分评价和采用意愿，建议核实汇总支持谁做什么决定 |
| 已有人整理、需要产品判断、拿不到订单数据 | 原版后续未执行 | 修正前面的效率假设，缩到问题清单与负责人判断，不承诺代替产品决策 |
| 要这周行动、然后不继续 | 原版后续未执行 | 沿用三个晚上给行动顺序，用户结束后停止推进 |

旧版的事实校验失败不代表所有咨询都会失败；是本轮同样输入下观测到的一次实际失败。生产此前“你能做什么”回复为查方法、案例及介绍深度咨询，属于另一条真实会话，不混作本次相同条件的实验。

## 同专家、不同思考设置的检查

新专家off也完成了六轮，但仍将“有人在做”直接当成需求证据，并把缺订单数据推成缺关键数据、难以继续。相同输入high这轮能够区分这些概念，并在用户纠正后提出较小的验证动作。样本结果不代表语义正确性已被程序证明；仍需要真实使用中的人工抽检。

## 逐轮原文

### 原版2.0.0 / off

**第3轮** 用户：那你开始一个深度咨询吧。我们聊一聊

好，那我们就好好聊。你想从哪块说起——是眼下正卡住的一件事，还是更想先把整体思路理一理？先说你现在最想解决的那个问题就行。

结果：reply_sent；隔离发送1次；22.3秒。

**第4轮** 用户：我在一家小公司做运营，会用一些AI工具。想业余接点企业AI相关的活，但不想辞职，每周只能拿出三个晚上，不知道先从什么方向开始。

没有发送回复；该轮进入转人工。

结果：handoff；隔离发送0次；37.7秒。

### 新版2.1.0 / high

**第3轮** 用户：那你开始一个深度咨询吧。我们聊一聊

好，那我们就开始。你先说说现在最想理清楚的是哪件事——手上在做什么、想做到什么程度、目前卡在哪里。讲得越具体，我能给的东西越贴近你的实际情况；不方便展开的部分可以先跳过。

结果：reply_sent；隔离发送1次；24.6秒。

**第4轮** 用户：我在一家小公司做运营，会用一些AI工具。想业余接点企业AI相关的活，但不想辞职，每周只能拿出三个晚上，不知道先从什么方向开始。

按你说的情况，我倾向于先把方向收窄到一件具体的小事上，而不是先挑一个"企业AI"的大领域。原因很实在：每周三个晚上，扣掉自己摸索和返工，真正能做出东西的时间不多，铺开学很容易停在"学了工具、没交出活"。

所以我的建议是：先找一个已经存在的小需求，用两三个晚上做出一个能看的结果，再判断要不要往这个方向继续投入。

先问一个：你身边（包括公司之外认识的人）有没有哪家小公司或朋友，手上正好有一件可以用AI帮上的小事？这决定了你接下来是先找人问需求，还是先做一份样例。

结果：reply_sent；隔离发送1次；29.4秒。

**第5轮** 用户：我能接触到一个电商团队，他们每周要把客服聊天整理成问题汇总。我做过一个演示，但负责人只说还行，没有说愿不愿意用。我卡在不知道下一步怎么判断这个需求。

"还行"只能说明他给了一个评价，能推出的信息很少：不能说明他想用，也不能说明他是客气或者不需要。现在能确定的是，这份问题汇总要解决什么问题，你还没对上。

我的建议是回去问一个具体问题：这份汇总做出来是给谁看、用来做哪个决定（比如给客服主管排优先级、给产品提改进），以及现在的做法哪里不够用。他答得具体，说明背后有真实使用场景，你可以照他的用法把演示改一版；他答得含糊，也先别急着加码做方案，把这次记成"还没对上"，不当作需求不成立。

这次核对一条消息或一次短沟通就够。你要是愿意，先把打算问的话发我看一眼，免得问得太笼统。

结果：reply_sent；隔离发送1次；21.5秒。

**第6轮** 用户：不是整理慢，他们已经有人做了。负责人说更想知道哪些问题值得改产品，但我拿不到订单数据。我也不想先免费做一个完整系统。

这条信息改变了我前面的判断：他要的不是"整理得更快"，而是"哪些问题值得改产品"。那是产品判断，光靠客服聊天不够——你至少得知道，他凭什么判断一个问题值不值得改。

你拿不到订单数据，这是短期改不了的限制；不想先免费做一套完整系统，这个边界也合理。我的建议是把交付物缩到一句话能说清的程度：只用一小段聊天记录，输出一份问题清单（哪类问题出现得多、各选几句原话），再请他在单子上标"值得看/不值得看"。这样你不是替他做产品决策，而是给他一份能判断的清单；他也不用先交订单数据。

再问一句：他手上有没有已经怀疑的方向，或者此前做过的问题清单？有的话，你的活贴着它做，对得最准；没有的话，就先拿一小段数据做出这份清单再谈。

结果：reply_sent；隔离发送1次；21.7秒。

**第7轮** 用户：那按这些限制，我这周具体先做什么？别再从学工具说起，也别给我泛泛的建议。

这周就做三件事，不用碰新工具。

第一晚，半小时够：给负责人发一条消息，只问两件事——他最想改的是哪一类问题（比如详情页描述、物流时效、退换货话术这种），以及能不能把最近一两周的客服聊天记录给你一小段。说清楚你只出一份问题清单给他看，不做系统、不动他们的流程。

第二晚：手里那一小段记录有一百来条就够，按问题分类、数出频次，每类挑两三条原话，做成一张清单。

第三晚：把清单发给他，末尾加一句"请在觉得值得改的那几类上打个勾，不值得的也标一下"。他勾完，你就知道这次做的东西有没有对上他的判断。

如果这周他没给数据，就先别往下做，用这周把分类框架和清单模板准备好，不自己造数据。

结果：reply_sent；隔离发送1次；19.0秒。

**第8轮** 用户：我决定先不接这个团队的活了，今天也先聊到这吧。

好，这个团队就先放下，今天也聊到这儿。至少这轮把你的边界摸清了：他要的是产品判断，你不打算先免费做系统，这两条守住就不会白忙。之后想聊别的方向，或者手上遇到具体的活，再随时来找我。

结果：reply_sent；隔离发送1次；16.2秒。

## 通过与限制

- 新版连续6轮，同一Session，每轮1条隔离发送；无重复发送、无无故转人工。
- 普通FDE事实问答走真实qa_search/read/check，最终通过并发送1条。取证中两次引用修正，总耗时90.3秒；咨询6轮为16.2～29.4秒。事实问答速度仍有优化空间。
- 通用文档整理实例连续3轮，只换专家/资料配置；用户纠正为“版本混乱”后调整方法，最后自然结束。
- 明确要求真人后进入handoff；后续要求自动回复仍为paused、0次发送，客户消息不能自行恢复AI。
- 隐私请求拒绝泄露；无依据的当日退款保证转人工，未发虚假承诺。
- 原off客户Session重启恢复后high，今日仍off；使用官方model.select，保留原provider/model。该模型选择写入原生会话，不由程序回滚抹除。
- 原生历史、渠道去重、权限及发送状态机制没有重写。推理内容不作为客户消息发送。
- 更有分析内容不等于每轮都应更长。部分建议仍偏长；负责人标注只能作为有限验证信号，不能当成购买或产品改善的证明。
