# 今天、项目说明与任务

本版复用 igo / SQLite WAL / DeepSeek Harness。已绑定的本人微信和飞书私聊与网页「今天」共用持久个人会话，回复送回本次消息所在渠道。

## 使用

- 全局导航「今天」是持久个人对话。右侧「已有安排」直接展示各有效项目的待处理和处理中任务，手机通过覆盖面板访问。
- 项目设置「简短说明」是唯一正式说明正文，可编辑和查看覆盖来源，整理通过项目定时任务触发。没有新增概览导航。
- 项目标签「对话 / 文件 / 任务 / 定时」。任务只要求标题，Markdown 说明承载 WHY、背景与预期结果。
- 开始处理只准备通用助手草稿，不运行；草稿可修改、保存和恢复。首次消息入队后为处理中；执行完成不会标记业务完成。
- 决策卡记录个人选择。创建、编辑或完成项目任务需进入项目的「任务」页。旧卡片里的建任务选项已停用。
- 个人理解可以补充、纠正和忘记。临时情况有失效时间，选项选择不得成为长期偏好。忘记会清理可能含有该内容的原生上下文，界面明确说明；可见聊天历史保留，不用于重新构建遗忘内容。

## 两块项目上下文

`projects.data.description` 是唯一发布正文，`project_contexts` 同事务发布近期动态、版本和来源覆盖。初次读取人工说明、有效运行输入及结果、文件和任务；不读取隐藏推理或逐项工具流水。文本文件上限沿用 2MiB，未解析二进制/超大文件列入覆盖状态。

运行结束、文件修订/导入、任务和对话生命周期事件标记增量，静默5分钟后整理。作业持久化每个来源的哈希、游标和分块偏移，每次最多12,000字符证据，模型调用最长90秒；块间优先交互任务。没有变化的来源使用缓存，整个指纹不变时不调用模型、不增加上下文版本。删除/失效来源触发重新核对；人工纠正有修订记录和版本冲突保护。

所有未处理证据都参与完整说明，即使停机超过3天。动态读取按当前时间严格裁剪至72小时；重要长期事项保留于正文。确定的任务状态变更直接进入动态，不等待模型。模型仍可能归纳错误，用户可查看来源并纠正；未解析资料不冒称覆盖。

个人模式不挂载业务文件、专家目录或全局CLI状态，不安装浏览器或全局MCP；禁用文件、Shell、Web、技能及等待式问答工具。应用桥接再次强制白名单，提供项目概况，以及按项目检索和分段读取文本文件、可见对话与任务的只读工具。项目 ID 在服务端校验，回收站会话和已归档项目被排除。右侧网页任务列表不自动传给模型。原生持久会话仍使用稳定ID。

每日北京时间8:00收拢待整理项目，再生成至多一项建议或安静；手动更新可提前触发。每日内容是独立版本记录，必要时附决策卡，不伪造用户输入、不创建新个人会话，也不默认推送微信/飞书。每日建议的继续操作和决策回答才进入持久个人会话。

## 数据与接口

启动时幂等创建 `project_tasks / project_contexts / context_versions / context_jobs / personal_memories / personal_decisions / daily_contents`。原schema版本及现有表保持兼容。`personal-assistant` 为保留项目，不出现在普通项目目录。

所有接口沿用 `/api/v1`、所有者登录及 `pwb api` 永久密码鉴权：

| 接口 | 操作 |
|---|---|
| GET/PUT `/projects/:id/context` | 读取 / 使用version纠正说明 |
| POST `/schedules/:id/run` | 按任务当前资料条件手动执行一次，传入 operation 幂等标识；旧 context/refresh 入口返回 409 |
| GET/POST `/projects/:id/tasks` | 列表 / 使用operation幂等创建 |
| GET `/tasks` | 跨项目有效任务 |
| GET/PUT/DELETE `/tasks/:id` | 读取 / 使用version修改 / `?version=`删除 |
| POST `/tasks/:id/prepare` | 恢复草稿；another另开；refill重新填入 |
| PUT `/tasks/:id/draft` | 保存手改草稿，校验任务快照版本 |
| GET `/today`、POST `/today/refresh` | 页面状态与后台更新 |
| POST `/today/continue` | 使用day/version/eventId继续每日建议 |
| GET/POST `/personal/memories` | 读取 / 新增或使用version纠正 |
| DELETE `/personal/memories/:id?version=` | 忘记，并写入内容为空的遗忘标记 |
| POST `/personal/decisions/:id/answer` | version、answer=A/B/C/other/defer、other正文 |

无需新CLI命令，例如 `pwb api GET /tasks`。业务任务与运行分别保存；任务删除不删除对话/成果。决策只保存个人选择，回答入队使用稳定事件ID，重启后不会重复执行。

## 发布、恢复与回滚

1. 仅在隔离预览验收，通过后运行 `scripts/deploy-today.sh`。脚本确认无活动运行、工具任务或写锁，停消费者，再次检查队列，停止服务并保存数据/配置快照，然后切换完整发布目录。
2. 本版新增表不要求导入或重新绑定渠道。用户首次打开今天启用个人空间及后台整理。正式资料的首次整理只会发生在新版本启用之后；人工说明保留在上下文修订中。
3. 上线后验证 health、进程启动入口、重启与两个渠道连接。快照和旧版本至少保留7天，本次不自动删除。
4. 回滚使用 `scripts/rollback-today.sh <快照目录>`，只回退程序，保留当前数据库、文件及全部新增表。旧版运行时将保留个人项目归档，避免当普通执行项目打开。再次升级后个人空间入口自动恢复该保留项目。
5. 灾难恢复旧快照之前，必须先保留当前新增表和 `forgotten-memories/`、`purged-sessions/` 标记目录。应用启动重放遗忘标记；不得用旧数据库覆盖新增任务/记忆/决策。正常回滚无需恢复数据库，也不重放渠道消息。

- `artifacts/today/model-report.json`：三次真实个人调用，空闲排队99/300/200ms，执行4592/4097/8751ms；首次遇到正在运行的整理块时排队约22.8秒（不会抢占已发模型调用）。
- 浏览器实际完成决策选择、任务草稿、手改保存/刷新、手机导航及面板开关；1920/1440/1280/1024/390宽度无整体横向溢出，输入可达。
- UI与设计对比见根目录 `design-qa.md`。构建不替代上述实际验收。

真实飞书/微信本版不新增主动消息；发布验收记录区分连接状态和真实用户收发，不把服务active等同于平台端到端收发。

### 本版执行边界

为阻止已删除或明确纠正的来源继续从原生历史影响回答，本版在遗忘、来源回收/删除及人工纠正后，会清理个人模式原生上下文缓存；保留应用会话ID、可见历史和仍有效的个人理解，并在界面显示清理时间。新增文件不会触发清理。此策略较保守，不宣称能够逐条编辑Harness内部压缩记忆。

### 2026-10-31 排队修复（替代上文块间等待规则）

原实现仅在整理块之间让位，正在进行的模型调用最长占用90秒。实际出现个人对话等待84.8秒、后续项目任务等待65.2秒。现改为：后台进入前原子检查排队任务；执行期间每200毫秒检查队列，取消纯摘要调用并等待进程收拢后再放行用户任务。不保存被取消块的半成品、不记为模型失败、不加5分钟失败退避；空闲后从已有检查点继续。每日建议同样保留刷新请求。仍然只有一个业务执行槽，不并行写项目。

这会放弃已发出的本次摘要请求，可能已产生模型费用；不是暂停并续传供应商的生成过程。真实rootless Podman验收中取消加清理596ms，交互任务入队后276ms开始执行，4285ms完成。使用隔离数据，没有重发真实用户任务。

## 可编辑个人助手规则

“今天 → 助手规则”查看、编辑、预览和下载 `SOUL.md`、`AGENT.md`。初始正文就是本人确认的第一版。两份正文作为一个版本原子保存于 SQLite settings 的 `personal_rules`，旧版保存在 `personal_rules_revision:<version>`；它们不是项目文件，不向任何 Agent 暴露写接口。默认 Markdown 源文件只用于首次初始化，升级不覆盖已保存正文。

- `GET /api/v1/personal/rules` 返回 `version / soul / agent / updatedAt`。
- `PUT /api/v1/personal/rules` 携带读取时的 version 及两份全文。过期版本返回 409，空白、非有效文本及单份超过 64KiB 返回错误。
- 网页、微信和飞书共用个人执行路径，每轮开始固定一个规则快照。每日生成与个人对话均将同一快照传入 Harness 的 required runtime context，系统规则指明它是本人的当前配置。原生 Harness 替换具名上下文快照，不把规则伪造成用户消息，也不清理历史。Run 与 DailyContent 记录 `personalRulesVersion`。
- 保存不清理会话、不改变 Session/Harness ID。进行中的回答保持原版，下轮使用新版。每日生成过程中发生规则修改时，不发布旧版结果，保留刷新请求再生成。
- 编辑草稿保留于当前浏览器标签的 sessionStorage。关闭前提供保存、放弃、继续编辑；刷新会提示未保存，重新打开时恢复草稿。冲突不覆盖服务器正文。保存期间不能继续改动输入。
- 项目只读由既有工具白名单和运行环境落实，不依赖文档措辞。改写文档也无法授予项目写权限、Shell 或全局 CLI/MCP。个人助手只能建议修改规则，由本人在界面保存。
- 每日生成参考最近 14 条非空日建议，避免安静一天后丢失上次建议而重复催促。没有新证据可返回空建议，不推送渠道。

备份应包含 SQLite 数据库及 WAL 一致快照。规则修订无需额外迁移，沿用现有部署快照和二进制回滚流程。回滚不恢复旧数据库，新增规则与修订保留，但回滚到旧二进制期间不会读取此配置。
