# 通用双向会话通信验收

2026-11-05。基线：正式组合 cloud-20261104-32-suite-white-78a6002。用户已授权开发、整体review、修复并在验收通过后上线。

## 最终行为

同一协议支持项目↔项目、今天↔项目。自由文本，不规定汇报栏目，不要求回信。只返回后台接收回执；接收方仅在自己决定发送时调用同一工具。原生会话保持原ID和历史。

复用inbox/Run，新增communication_roots保存事务计数和撤销状态；单独存控制记录避免saveRun的整段JSON保存覆盖并发计数。委托确认保存在原消息上，界面使用已有确认交互，不建立第二套审批模块。旧任务和客户运行默认不获通信权限。

## Review发现与修复

完整检查新核心及Submit/Route、调度领取、SDK恢复、工具注册与宿主bridge、归档和资料查询、个人记忆、删除及发布回滚的直接消费者。

1. 原有资料查询及归档把所有新输入称为用户表达：增加Agent来源与消息编号，个人记忆排除Agent输入。
2. 只读项目轮跳过了宿主runtime挂载，可能使用镜像内旧工具目录：补齐独立runtime挂载，宿主继续逐工具拒绝写入。
3. 旧版不认识Agent元数据可能按普通项目权限执行：新增通信协议标识及既有控制器中的回滚冻结和触发器保护。
4. 取消与接收/领取竞争（含尚未发出第一条消息时停止）：持久撤销后复核；处理中收拢执行器，已取消的消息不能重新路由。
5. 来源移除后正文及原生上下文仍可引用：清理因果链消息及关联成果，在目标下次执行前清理受影响原生上下文并显示通知，原Session/Harness ID保持；工作台其他原始记录仍可查询。
6. 模型把站内文字通信误认为微信/飞书外发：明确工具语义，并以实质分析回传验证；外部发送仍按原授权。

修复后再次只读复核完整差异：No findings. 模型对业务意图、何时值得主动发送、资料是否过时的判断仍由模型及本人规则承担，程序不宣称能证明任意自然语言授权范围。
