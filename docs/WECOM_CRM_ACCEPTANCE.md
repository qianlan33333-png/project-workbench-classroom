## 隔离浏览器旅程

实际运行两套产品后端、工作台 SQLite、独立 PostgreSQL 16、签名 HTTPS 双向请求和发行构建的 CRM 侧边栏。使用临时测试员工与客户、测试登录会话和真实身份归属检查。企微 JS-SDK、模型推理与客户外发为确定性替身。

| 操作 | 观测结果 |
|---|---|
| CRM 默认关闭，打开客户侧边栏 | 整个入口隐藏，恢复请求 0 次 |
| 进入管理设置 | 可看到当前绑定的双端预置地址，经双向签名 probe 后启用 |
| 会话转人工，客户再发 3 条消息 | 工作台记录 3 条暂停历史，通知抵达 CRM，无新增应答运行 |
| 从实际侧边栏点击「恢复 AI」 | 仅 1 个恢复 POST，页面从 CRM 重新读取工作台状态；点击时新增运行 0、客户外发 0 |
| 客户提出一个新问题 | 1 个新 Run，执行器收到暂停区间的指定事实，1 条对应的测试发送回执 |
| 再次关闭 CRM | 侧边栏隐藏；工作台会话保持 auto。全旅程确认 2 条 CRM 状态通知 |

本次操练使用 Chrome 的设备 SDK 替身。不能据此判断真实企业的 OAuth 可信域名、微信设备 SDK、员工身份映射或真实客户收发。此前仅针对原企微连接器做过的真实验证另见 [单客户旧版试点](WECOM_CONNECTOR_ACCEPTANCE.md)。
